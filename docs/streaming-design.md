# 流式护栏接入契约

## 范围与选择

采用现有 AGT ChunkBufferEngine 的有界字面窗口算法，不重写匹配器；框架仅依赖新增 spec 可选能力。完整缓存使用参考引擎的有界缓冲，兼容完整检查与输出改写。

LangChain4j 通过 guardStreaming(options) 显式启用，初次支持 TokenStream。Flow.Publisher 走另一套异步状态机，本次在构建阶段明确拒绝护栏组合，不能因解除原有流式限制而绕过检查。

## 模式

- STRICT：完整 MODEL_OUTPUT 通过后，最终轮再执行 AGENT_OUTPUT，才向业务释放最终文本。支持现有输出 Guardrail 的重试与改写。
- WINDOW：仅显式 StructuredPolicy 的输出字面拒绝规则，保留最长模式长度减一的未释放尾部。有限窗口不能证明任意语义规则的全文安全。完整终态检查仍执行，已发送前缀不能撤回。
- WINDOW 拒绝输出替换、动态 GuardPolicyResolver、额外的非覆盖输出 Guard、多个流式 Provider、未知评估器和输出 Guardrail 组合；使用 STRICT 可以保留这些完整检查能力。

## 生命周期与安全要求

- 每次模型调用前检查合并默认参数后的完整 MODEL_INPUT，不恢复已过滤工具。
- 每轮建立独立流缓冲和轮次，工具循环、输出 Guardrail 重试同样经过检查。
- 文本在业务 partial 回调前检查；思考、原始事件、工具参数预览回调被抑制。
- 完整工具调用回调不提前执行；完整 MODEL_OUTPUT 检查后，根据有效工具调用执行 TOOL_INPUT / TOOL_OUTPUT。护栏开启时先通过完整响应检查，再按框架配置串行或并行调度。
- 完成时先 seal 验证片段与完整正文一致，再执行完整检查，最后 complete 释放尾部。
- 终止、取消、缓冲超限或检查失败后，不再向业务发送片段或完成回调，错误通知至多一次；有上游 StreamingHandle 时尽力取消，否则停止接收和释放。
- 原生输出 Guardrail 的重试经过模型装饰器；STRICT 释放最终检查后文本，不重复回放原始片段。
- 工具、内部记忆与业务返回必须使用改写结果；不支持的改写明确失败。

## 配置

GuardStreamOptions.strict() 默认正文上限 1048576 个 UTF-16 单元；strict(limit) 自定义上限。
window() 默认每 64 个新增 UTF-16 单元、标点或 50ms 触发检查，上限 4096；window(chunk, waitMillis, limit) 可配置。AGT 窗口沿用底层词表与 65536 缓冲上限，词表容量不足或缓冲不够时初始化失败。

等待超时只触发检查，不强制释放未判定尾部。窗口为本地同步规则，定时回调串行运行，不能把远程检测无限排队。调度器由单轮缓冲持有，完成或失败时关闭。

## 验收

1. 跨片段禁止字串不泄漏，超时不会释放未判定尾部，EOF 正常释放安全尾部。
2. STRICT 完整输出拒绝与改写、容量上限、片段不一致明确失败。
3. WINDOW 不兼容配置构建失败，其他 Provider 输出规则不会被静默跳过。
4. LangChain4j 用户输入、完整模型输入输出、工具前后和最终输出全部覆盖；工具无提前副作用。
5. 回调异常、错误后迟到片段、取消、工具循环与模型重试不漏检、不重复终态通知。
6. 原非流式与 YAML/SPI 自动装配保持回归；SDK 在真实 JDK 8 和 JDK 17 验证，生产 class 为 major 52。
7. 提供 .env 驱动的实际流式入口以及本地 SSE 测试；没有真实凭证时不宣称外部 LLM 已验证。
